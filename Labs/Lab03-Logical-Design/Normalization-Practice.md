# Lab 3 第二次：无损连接与依赖保持

**预计用时：75～100 分钟。**

## 本次目标

分别证明关系分解是否无损、是否保持依赖，并用反例解释两者为何不是同一个性质。

## 开始前准备

准备[第一次练习](Lab03.md)的模式与依赖集，复习依赖投影、属性闭包和二元无损分解判据。结果继续写入 `Work/Lab03/设计.md`。

## 任务一：检查项目中的一次分解（25 分钟）

若自己的设计发生过分解，写出原关系R、依赖集F和分解后的关系。二元分解按公共属性决定某一边的判据证明无损；多步分解逐步说明，或采用教材的chase方法。

将F投影到子关系，合并为G；对原F中每条X→Y，计算X在G下的闭包，检查是否包含Y。只验证候选码能否决定全部属性还不够。

**本任务的结果：一次分解的两个独立判断及推导。若没有自然案例，注明“项目未作分解”，改用任务二完成全部推导，不必人为破坏项目。**

## 任务二：完成独立小题（35 分钟）

```text
R(A, B, C)
F = { AB → C, C → B }
分解为 R1(C, B) 和 R2(A, C)。
```

依次求全部候选码、判断原关系最高范式、判断分解是否无损、判断是否保持依赖。每个结论给推导，不能只写是或否。

**本任务的结果：四项结论及闭包、范式和分解依据。这是独立练习，不是项目预设模式。**

## 任务三：构造反例并解释取舍（20 分钟）

针对任务二中未保持的依赖，构造两份各自满足投影依赖的子关系，使连接结果违反该原依赖。若卡住，先从每边两行开始尝试。

再解释：既然分解无损，为何仍可能不保持依赖？在工程中选择保持依赖的3NF方案，可能减少哪些检查工作？

**本任务的结果：一组具体元组和一段区分两个性质的解释。**

- [ ] 原依赖逐条检查，没有只验证候选码。
- [ ] 反例的子关系局部合法，连接后确实违反原依赖。
