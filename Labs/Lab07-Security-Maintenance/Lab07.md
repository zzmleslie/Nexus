# Lab 7：权限控制与备份恢复

**分两次完成。** 本页权限实验约60～90分钟；第二次按[恢复练习](Backup-Restore.md)验证备份。

## 本次目标

使用数据库用户、角色和视图限制访问，通过独立账号与撤权测试确认边界，并区分DBMS权限与业务身份。

## 开始前准备

准备Lab 5的公开活动视图，以及可管理专用测试账号的本地环境。无管理权限时更换自己可控的测试环境，不借共享业务管理员账号实验。

## 任务一：明确要保护的范围（10分钟）

写出本次授权目标：只读测试账号能查公开活动视图，不能直接查学生基础资料、修改活动或创建表。检查视图没有不必要的个人信息。

另举一例说明社群负责人这种业务身份，与能否SELECT某视图的数据库权限并非同一概念。

**本任务的结果：一份允许/拒绝清单，以及业务身份与DBMS权限的区别说明。**

## 任务二：建立角色与测试账号（25分钟）

编写 `Work/Lab07/permissions.sql`：创建只读角色，只授予目标视图的SELECT；创建专用用户，授予角色，并设置默认角色或在新连接中显式激活。

用管理连接查看授权，用测试连接确认CURRENT_USER()与CURRENT_ROLE()。真实密码仅在本地设置，提交脚本保留占位提示。[角色说明](https://dev.mysql.com/doc/refman/8.0/en/roles.html)

说明视图以谁的权限访问底层对象；SQL SECURITY DEFINER要求定义者存在且有必要权限，不会自动按学生身份过滤数据。

**本任务的结果：权限脚本，以及独立账号匹配、角色激活与视图安全语义的记录。**

## 任务三：验证访问并撤权（25分钟）

用测试账号逐条执行查视图、查学生基础资料、修改活动、创建表。仅第一项应成功；其他若成功，查直接或继承权限并修正。

撤销角色或角色中的视图SELECT，重新建立测试连接后再查，确认原访问被拒绝。不能只检查GRANT文本而不验证行为。

**本任务的结果：四项访问测试及一次撤权复查的预期/实际结果。**

## 任务四：说明未实现的业务授权（10分钟）

回答是否已实现“学生只能改自己的报名”“负责人只能改自己社群”。若没有，说明还需要什么可信身份与受控路径，可讨论存储过程、服务端校验或特定视图，不要求开发后端。

**本任务的结果：已保障与未保障范围的简短说明，不将视图只读测试当作完整行级安全。**

## 完成与提交

在 `Work/Lab07/` 保存 `permissions.sql` 与 `笔记.md`，记录各任务证据，不保存密码。

- [ ] 使用真正不同的账号验证。
- [ ] 角色激活、访问拒绝和撤权均测试。
- [ ] 公开视图无不必要个人信息。
- [ ] 业务授权的剩余边界说明准确。

选做：比较拼接输入与参数化查询，说明为何输入应作为值绑定，而非作为SQL片段执行；不要求搭建网站。
