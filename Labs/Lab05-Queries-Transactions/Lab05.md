# Lab 5：业务查询与事务

**分两次完成。** 本页查询练习约90～110分钟；第二次按[事务练习](Transactions.md)处理并发报名。

## 本次目标

用自己的数据库完成六个业务查询，正确处理历史、空集合、去重与统计；比较两种反查询写法，并建立一个公开查询视图。

## 开始前准备

使用Lab 4的表与小规模数据，复习连接、分组、聚合、子查询和视图。业务含义以[业务背景与需求](../../00-业务背景与需求.md)和自己的已记录政策为准。

## 任务一：实现六个业务查询（55分钟）

在 `Work/Lab05/queries.sql` 实现以下查询。每题先给定参数、用几条数据手算预期，再执行比较：

1. 输入学生标识，查询其当前有效社群资格，并另外查询已结束的成员经历。
2. 输入活动标识，查询当前正式名单，按受理时间排序；同一时刻使用稳定的并列规则。
3. 列出每场活动的当前正式人数与剩余名额，无人报名活动也必须出现。
4. 查询当前正式人数至少为2的活动。
5. 输入活动举办开始时间区间[a,b)，查询没有有效报名该区间内任何活动的学生。这里报名按查询时当前有效状态计，取消历史不计；先使用NOT EXISTS。
6. 输入学生与活动，按时间列出每次报名受理、取消和重报经过，不能只返回最终状态。

至少用样例覆盖同名、无人报名、取消重报和区间端点。第3题关注外连接及COUNT(*)与COUNT(列)的区别；第4题区分WHERE与HAVING；第6题注意UNION与UNION ALL是否会改变真实动作数量。

**本任务的结果：六组查询，每组有输入、预期、实际结果及不一致时的修订。**

## 任务二：比较反查询与NULL行为（15分钟）

将第5题改写为外连接版本，与NOT EXISTS在同一数据上比较；测试既无记录、又有取消历史的学生。

再构造一个NOT IN的被比较集合中含NULL的例子，记录结果并解释。不能因为一种写法能执行就认为语义总相同。

**本任务的结果：两种等价查询的结果核对，以及一个NULL影响的具体例子。**

## 任务三：建立并验证视图（20分钟）

选择一个公开活动查询，写成 `view.sql`。视图不包含学生私人资料；修改相关基础数据后重新查询，比较结果变化。

普通视图不是独立保存的结果副本，聚合等因素也可能使其不可更新。今天验证查询行为，权限在Lab 7处理。[可更新视图说明](https://dev.mysql.com/doc/refman/8.0/en/view-updatability.html)

**本任务的结果：视图定义，以及修改基础数据前后的查询结果。**

## 完成与提交

提交 `Work/Lab05/queries.sql`、`view.sql`；在SQL注释或 `笔记.md` 写验证记录，不要求截图。

- [ ] 六项业务查询均运行并对照预期。
- [ ] 无人报名活动未被漏掉，历史尝试未重复计入当前人数。
- [ ] 反查询在样例上等价，NULL影响有实例。
- [ ] 视图能够反映基础数据变化。

选做，任选一项：用CTE改善一条查询可读性；用窗口函数对各社群活动按人数排名并解释并列；查询报名指定范围全部活动的学生并说明范围为空时的结果。
